# Design System

**Status:** Done — Phase 1, Step 2. Revisited during [[Codebase-Audits|Codebase Audits]].

Dark-mode-first luxury theme — "Midnight Navy & Champagne Gold". Sharp, zero-radius corners (`--radius-lg/md/sm: 0px`, theme-independent) reinforce the luxury/precision aesthetic. Uses `tailwindcss-animate` plugin for animation utilities.

## Light/Dark Theme Toggle
- **Restructured `src/app/globals.css`** to the standard shadcn/Tailwind v4 dual-theme pattern: raw color variables (`--background`, `--foreground`, `--card`, `--primary`, etc., unprefixed) are now defined once under `:root` (light) and again under `.dark` (dark), and a single `@theme inline { --color-background: var(--background); ... }` block maps each to the `--color-*` custom property Tailwind's utilities (`bg-background`, `text-primary`, …) actually read. Previously the `--color-*` values were hardcoded directly in `@theme` with no light variant at all — this is a structural change, not just new values alongside the old ones.
- **Light palette** (new): background `#F7F3EC` (warm ivory), foreground `#101827` (near-navy), cards `#FFFFFF`, primary `#A87C1F` (a slightly deepened gold for AA contrast on the light background — the dark-mode `#C69B3C` gold is too light to read reliably on white), destructive `#B0182F`, success `#0E9A6E`. **Dark palette is unchanged** from the original values (`#06101E` background, `#C69B3C` gold, etc.) — moved into `.dark` verbatim.
- `src/components/theme-provider.tsx` — thin wrapper around `next-themes`' `ThemeProvider` (`attribute="class"`, `defaultTheme="dark"` to preserve the brand's dark-first default, `enableSystem`), mounted in `src/app/layout.tsx` (wrapping `LanguageProvider`, with `suppressHydrationWarning` on `<html>` — required by `next-themes` since the theme class is set client-side before hydration).
- `src/components/theme-toggle.tsx` — a single icon button (no new shadcn install) cycling Light → Dark → System → Light (`Sun`/`Moon`/`Monitor` from `lucide-react`), added to the dashboard header ([[Portfolio-Dashboard|Portfolio Dashboard]]'s `dashboard-header-controls.tsx`, alongside Privacy and Language) and the marketing landing page header (`src/app/page.tsx`).
- **Removed System option (later change)**: `theme-provider.tsx`'s `enableSystem` is now `false`, so `next-themes` never resolves `prefers-color-scheme`. `theme-toggle.tsx`'s `ORDER`/`ICONS`/`LABELS` dropped `"system"`/`Monitor` entirely — it's now a plain two-state Light/Dark toggle (`toggle()` flips directly between them instead of cycling a 3-item array), defaulting to `"dark"` instead of `"system"` when `theme` is still unset. Verified visually: landing page loads dark by default, one click switches to light (sun icon, ivory palette), a second click returns to dark — no System step in between, no console errors.
- **Hardcoded-color audit**: grepped the whole `src/` tree for non-semantic Tailwind color classes and raw hex values outside `globals.css`. Found and fixed one: `portfolio-table.tsx`'s Performance column used `text-emerald-500`/`text-red-500` instead of `text-success`/`text-destructive` — switched to the semantic tokens so gain/loss coloring now follows the active theme. Every other color reference in the app (Recharts strokes/fills in `asset-detail-view.tsx`, the login page's radial gradient) already used `var(--color-*)` lookups, so they automatically pick up both palettes with no changes needed.
- Verified visually in the browser: cycling the toggle through Dark → System → Light on the landing page correctly re-themed the whole page (ivory background, navy headline text, gold accent preserved, buttons still sharp-cornered) with no console errors. Not yet checked against every individual page (asset details, settings, MFA screens) in light mode — worth a pass before relying on it everywhere.

## Global App Shell: Responsive Sidebar, Full-Width Layout (2026-09-29)

Steve wanted the app to match Finary's premium, data-dense feel — the app was rendering every page (dashboard, asset details, settings) as a narrow centered column with no persistent navigation chrome, each page instead duplicating its own top header (logo, Settings link, Sign Out button) inline.

- **New `src/components/app-sidebar.tsx`** — a single client component rendered once from `app/dashboard/layout.tsx` (previously just a `PrivacyProvider` passthrough, now a flex shell: `<AppSidebar/>` + `<main className="min-w-0 flex-1">{children}</main>`), replacing every page's duplicated top-nav bits:
  - `lg+`: full sidebar (logo + wordmark, icon+label nav, Sign Out footer), `w-64`.
  - `md`–`lg`: same sidebar collapses to icon-only (`w-16`, labels `hidden lg:inline`, `title=` tooltip instead) — width driven purely by Tailwind breakpoints with `transition-[width] duration-300`, no JS toggle needed for this axis.
  - below `md`: sidebar itself is `hidden`, replaced by a slim top bar (logo + hamburger `Menu`/`X` icon) and a `useState`-driven slide-down panel with the same nav links + Sign Out.
  - Uses only existing semantic tokens (`bg-card`, `border-border`, `text-foreground`/`text-muted-foreground`, `bg-primary/10` for the active-route highlight via `usePathname()`) and the existing `Button`/`cn` primitives — no hardcoded colors, so it inherits `next-themes` light/dark automatically like everything else in this file.
  - Nav items are just Dashboard (`/dashboard`) and Profile Settings (`/dashboard/settings`) — the app's only two real top-level routes; Sign Out reuses the existing `logout` server action (`app/auth/actions.ts`).
- **Full-width layout expansion**: removed the narrow-column wrappers that were producing the "vertical rectangle" look —
  - `asset-detail-view.tsx`'s root `mx-auto max-w-3xl` (768px cap) → `w-full`. This was the biggest offender: the asset details page (Overview/Analysis/Tenancy/Specifications) was hard-capped at 768px regardless of screen size.
  - `dashboard/settings/page.tsx` and `dashboard/mfa/page.tsx`'s outer `min-h-screen bg-background` wrappers (redundant now that `dashboard/layout.tsx` provides both) → `w-full` with the same `px-4 sm:px-6 lg:px-8` responsive gutter used elsewhere. The settings *form* itself keeps its own `max-w-2xl` — a profile form reads better narrow; only the page shell went full-width.
  - `dashboard/page.tsx` was already full-width (no cap existed there) — only its duplicated header nav (logo, Settings link, Sign Out) was removed, now redundant with the sidebar.
  - Ten identical `grid grid-cols-1 gap-4 sm:grid-cols-2` DetailField grids across `asset-detail-view.tsx` (Specifications tab's property/vehicle detail cards) gained `xl:grid-cols-4` so they don't look sparse now that the page can be 1600px+ wide — the existing 3-/4-column grids elsewhere in that file already scaled correctly and were left alone.
- **21st.dev integration explicitly skipped this pass**: the 21st.dev MCP's free tier is metered at 2 `get_component` calls/day, so no live fetch was spent on an unreviewed autonomous overhaul — the sidebar/shell above was hand-built from existing shadcn primitives + semantic tokens instead, which already satisfies the "no hardcoded colors, theme-aware" requirement. Worth spending an actual 21st.dev lookup later, with Steve reviewing the result, if a more polished sidebar/dashboard-shell primitive is wanted.
- Verified live in the browser at three breakpoints (1600px, 900px, 375px mobile) against a real seeded asset (Ellington House) and the dashboard: full sidebar with active-route highlight at desktop width, icon-only collapse at tablet width, top bar + working hamburger slide-down at mobile width; the asset details page's Specifications tab now visibly fills the wide viewport instead of sitting in a centered 768px column. `tsc --noEmit`, `eslint`, and `npm run build` all clean.

## Comfort (accessibility) display mode (2026-10-02)

- **Toggle:** `components/comfort-mode-toggle.tsx` — a labelled `Switch` ("Comfort mode", `comfort_mode`/`comfort_mode_desc` in all 9 languages) in the dashboard header controls, the login page and the home page.
- **Persistence:** `lib/comfort-mode.ts` stores the key `opes-comfort-mode` (`on`/`off`) in `localStorage` and mirrors it to `<html data-comfort="on">`. A tiny inline script in `app/layout.tsx`'s `<head>` applies it before first paint (no flash); the toggle reads it through `useSyncExternalStore` (so it also follows other tabs). Storage access is wrapped in try/catch.
- **What changes** (all CSS at the end of `app/globals.css`, keyed off the attribute, so every page and dialog is covered without touching components):
  - **Type:** root font size 130% — Tailwind is rem-based, so text, spacing and controls all scale; line-height 1.6.
  - **Contrast:** light = pure white background, black text, `--muted-foreground` #2B2B2B (no light grey), darker gold/green/red; dark = pure black, white text, `--muted-foreground` #EDEDED, brighter accents; borders/inputs/ring strengthened; placeholders solid; 3px focus outline.
  - **Touch targets:** buttons, `role=button/tab/menuitem/option`, selects, inputs and standalone links get `min-height/min-width: 48px` plus a 2px margin; small switches/checkboxes get a 48px hit area (pseudo-element; native checkboxes are enlarged instead).
  - **Icons:** icon-only buttons (a lone SVG child) show their `aria-label` — else `title` — as visible text via `::after` and widen to fit.
- **Verified (dev server, browser pane, login page, dark theme):** toggling set `data-comfort="on"`, root font 16px → 20.8px, background pure black, `localStorage` = on, every visible control ≥48px tall except the native "remember me" checkbox, which this pass then enlarged (re-check not done), icon buttons showed their text. **Not verified:** the dashboard and dialogs with real data (auth wall), light-theme contrast by measurement, a reload (persistence logic is simple but not re-run), and screen-reader behaviour.
- **Known limits:** the `::after` label relies on `:has()` (all current browsers); inline links inside paragraphs keep their text size (exempt from the 48px rule); the sidebar's collapsed icon-only mode and any very wide table may need a manual look at 130%; `text-foreground/60`-style opacity utilities, if any, are not overridden.

A tier selector sits above Sign out (rail + drawer); labels are `tier_*` keys in `lib/i18n.ts` (EN/FR).
