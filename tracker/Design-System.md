# Design System

**Status:** Done — Phase 1, Step 2. Revisited during [[Codebase-Audits|Codebase Audits]].

Dark-mode-first luxury theme — "Midnight Navy & Champagne Gold". Sharp, zero-radius corners (`--radius-lg/md/sm: 0px`, theme-independent) reinforce the luxury/precision aesthetic. Uses `tailwindcss-animate` plugin for animation utilities.

## Light/Dark Theme Toggle
- **Restructured `src/app/globals.css`** to the standard shadcn/Tailwind v4 dual-theme pattern: raw color variables (`--background`, `--foreground`, `--card`, `--primary`, etc., unprefixed) are now defined once under `:root` (light) and again under `.dark` (dark), and a single `@theme inline { --color-background: var(--background); ... }` block maps each to the `--color-*` custom property Tailwind's utilities (`bg-background`, `text-primary`, …) actually read. Previously the `--color-*` values were hardcoded directly in `@theme` with no light variant at all — this is a structural change, not just new values alongside the old ones.
- **Light palette** (new): background `#F7F3EC` (warm ivory), foreground `#101827` (near-navy), cards `#FFFFFF`, primary `#A87C1F` (a slightly deepened gold for AA contrast on the light background — the dark-mode `#C69B3C` gold is too light to read reliably on white), destructive `#B0182F`, success `#0E9A6E`. **Dark palette is unchanged** from the original values (`#06101E` background, `#C69B3C` gold, etc.) — moved into `.dark` verbatim.
- `src/components/theme-provider.tsx` — thin wrapper around `next-themes`' `ThemeProvider` (`attribute="class"`, `defaultTheme="dark"` to preserve the brand's dark-first default, `enableSystem`), mounted in `src/app/layout.tsx` (wrapping `LanguageProvider`, with `suppressHydrationWarning` on `<html>` — required by `next-themes` since the theme class is set client-side before hydration).
- `src/components/theme-toggle.tsx` — a single icon button (no new shadcn install) cycling Light → Dark → System → Light (`Sun`/`Moon`/`Monitor` from `lucide-react`), added to the dashboard header ([[Portfolio-Dashboard|Portfolio Dashboard]]'s `dashboard-header-controls.tsx`, alongside Privacy and Language) and the marketing landing page header (`src/app/page.tsx`).
- **Removed System option (later change)**: `theme-provider.tsx`'s `enableSystem` is now `false`, so `next-themes` never resolves `prefers-color-scheme`. `theme-toggle.tsx`'s `ORDER`/`ICONS`/`LABELS` dropped `"system"`/`Monitor` entirely — it's now a plain two-state Light/Dark toggle (`toggle()` flips directly between them instead of cycling a 3-item array), defaulting to `"dark"` instead of `"system"` when `theme` is still unset. Verified visually: landing page loads dark by default, one click switches to light (sun icon, ivory palette), a second click returns to dark — no System step in between, no console errors.
- **Hardcoded-color audit**: grepped the whole `src/` tree for non-semantic Tailwind color classes and raw hex values outside `globals.css`. Found and fixed one: `portfolio-table.tsx`'s Performance column used `text-emerald-500`/`text-red-500` instead of `text-success`/`text-destructive` — switched to the semantic tokens so gain/loss coloring now follows the active theme. Every other color reference in the app (Recharts strokes/fills in `asset-detail-view.tsx`, the login page's radial gradient) already used `var(--color-*)` lookups, so they automatically pick up both palettes with no changes needed.
- Verified visually in the browser: cycling the toggle through Dark → System → Light on the landing page correctly re-themed the whole page (ivory background, navy headline text, gold accent preserved, buttons still sharp-cornered) with no console errors. Not yet checked against every individual page (asset details, settings, MFA screens) in light mode — worth a pass before relying on it everywhere.

## Categorical chart colors (Phase 2)
Added `--chart-1` through `--chart-5` (light and dark variants, exposed as `--color-chart-N` via `@theme inline`, same pattern as every other token here) for the new [[Broker-Trade-Import|Portfolio Performance stacked area chart]] — a 5-color categorical palette extending the existing gold/navy/ivory system, varying in lightness (not just hue) for colorblind tolerance. No token of this kind existed before this feature needed one.

## Logo & Brand Marks
Steve initially supplied separate light/dark logo files (`OpesWealth_Light Mode Logo.jpg` / `OpesWealth_Dark Mode Logo.jpg`), which used the standard `block dark:hidden`/`hidden dark:block` swap. **Superseded (2026-09-28)** by a single transparent-background logo, `./Logo/OpesWealth_No Background Logo.png` — a gold "W" wordmark that reads correctly against both the ivory light background and navy dark background with no swap needed, simplifying every consumer back down to one `<Image>` tag.
- `public/logo.png` / `src/app/icon.png` replace the old `logo-light.jpg`/`logo-dark.jpg`/`icon.jpg` (deleted). **Also deleted `src/app/favicon.ico`** — the leftover default Next.js/Vercel favicon, which was silently taking priority over the custom `icon.*` file-convention route and was the actual reason the browser tab icon never updated in the earlier pass. Confirmed via `npm run build`'s route list: `/icon.png` is generated (previously `/icon.jpg`), and there's no more `favicon.ico` route.
- **Auth pages** (`src/app/login/page.tsx`, `src/app/reset-password/page.tsx`) and the **dashboard header** (`src/app/dashboard/page.tsx`) — each dropped its light/dark `<Image>` pair for a single `<Image src="/logo.png" alt="Opes Wealth" width={...} height={...} priority />` (80×80 on auth pages, 32×32 in the dashboard header, same sizing as before). `priority` added since the logo is above-the-fold on every one of these pages.
- **Theme toggle added to the login page**: `src/app/login/page.tsx` now imports the existing `ThemeToggle` (`src/components/theme-toggle.tsx` — already used in the dashboard header, a self-contained `"use client"` component reading/writing `next-themes` state, safe to drop into this server component as-is) and positions it `absolute right-4 top-4` over the page. Lets a visitor pick light/dark before they've signed in, rather than only after landing on the dashboard. `reset-password`'s guard clause (redirect-to-`/login` without a real recovery session) meant it couldn't usefully get its own toggle in this pass — a signed-out visitor never lingers there anyway.
- **Verified live**: login page in both light and dark mode via the new in-page toggle (single logo reads correctly against both backgrounds, no flash of the old two-image markup), dashboard header (single 32×32 mark, theme persisted across navigation), `/icon.png` confirmed served directly (2048×2048). `reset-password`'s own render still can't be exercised live in this mock-auth dev environment (same gap as before) but shares the exact same single-`<Image>` JSX pattern as the verified pages.
- `tsc --noEmit`, `eslint .`, and `npm run build` all clean after this change.
- **Universal rollout + sizing pass (2026-09-28)**: the logo file itself was updated again (same path, refreshed artwork); re-copied to `public/logo.png`/`src/app/icon.png`. Landing page (`src/app/page.tsx`) previously had no logo at all — added a small 32×32 mark in the header next to the "Opes Wealth" wordmark, and a large 140×140 hero mark above "Private Wealth, Clearly Seen" (was plain text before). Login page's top-left corner logo (in the decorative left panel) was removed entirely per explicit request — only the one above the sign-in card remains; the existing `ThemeToggle` top-right was already in place from the prior pass, not re-added. Dashboard header's logo resized from 32×32 to 40×40 (`className="size-10"`) to exactly match the adjacent `Avatar size="lg"` (Tailwind `size-10`), which it previously didn't. `tsc --noEmit`/`eslint .` clean; verified live in the browser (landing page hero + header, login page's single remaining logo + ThemeToggle, dashboard header logo/avatar pixel-matched).
