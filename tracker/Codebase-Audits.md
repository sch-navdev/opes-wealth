# Codebase Audits

**Status:** Ongoing — periodic review/cleanup passes, not a shippable feature in itself.

### 2026-09-21 — Codebase Audit & Cleanup Pass
A full review pass (frontend/design-system consistency, dead-code/"AI slop", and config/migrations consistency — three parallel audits) was run before any changes, per an explicit user request. Full findings and the approved plan live at the time of writing in the session's plan file; summary of what shipped:
- **Root page rebuilt**: `src/app/page.tsx` was still 100% unmodified `create-next-app` boilerplate (wrong theme, dead Vercel/Next.js links) — the single biggest finding. Replaced with a themed landing page (Midnight Navy & Champagne Gold, brand name, one-line value proposition, "Sign In" CTA to `/login`). `src/app/layout.tsx` metadata (`title`/`description`) rebranded from "Create Next App" to Opes Wealth.
- **Design-token fixes**: `card.tsx` (`rounded-xl` → `rounded-lg`) and `checkbox.tsx` (`rounded-[4px]` → `rounded-sm`) now correctly resolve through the theme's `--radius-*` variables (0px), instead of rendering visibly rounded corners contrary to the stated design system. `button.tsx`/`badge.tsx` destructive variants now use the `text-destructive-foreground` token instead of a hardcoded `text-white`. The champagne-gold outline treatment (`border-primary text-primary hover:bg-primary/10`), previously applied ad hoc per call-site, is now baked into `Button`'s `outline` variant itself — "Sign Out", "Sign Up", and the crop dialog's "Cancel" now render consistently with "Send Verification Link", "Register Passkey", etc., and every now-redundant per-call-site override was removed. See [[Design-System|Design System]].
- **Robustness/accessibility fixes**: `dashboard/settings/page.tsx` no longer uses a `user.email!` non-null assertion (redirects to `/login` if email is ever absent instead). `dashboard/page.tsx`'s liability-row class list now uses `cn()` instead of string concatenation. `mfa.ts`'s `currentAuthenticationMethods` check was tightened here to drop a speculative `"passkey"` method value — **later reversed**: a real device login confirmed `"passkey"` genuinely occurs, so it's back (see [[Authentication-Security|Authentication & Security]]). `profile-form.tsx`: the address "Country" combobox now has a properly associated `<Label htmlFor>` (via a new `id` prop on `CountryCombobox`), and the phone-verification stub now shows inline status text instead of firing a native `alert()`. Two-column grids in `profile-form.tsx` (name row, address grid) now stack on narrow screens (`grid-cols-1 sm:grid-cols-2`); the dashboard header now wraps instead of forcing a single row. See [[Profile-Settings|Profile & Settings]].
- **Passkey/TOTP UI separation**: see [[Authentication-Security|Authentication & Security]].
- **Dead code removed**: `src/components/ui/form.tsx` and its dependencies (`react-hook-form`, `@hookform/resolvers`, `zod`) were installed in an earlier task but never adopted anywhere — every real form in this app is hand-rolled with `useState`/`FormData`. Deleted and uninstalled.
- **Deferred (lower priority, not done in this pass)**: adding a `.env.local.example`, rewriting `README.md` (still generic `create-next-app` boilerplate), and trimming this document's duplication between "Architecture Log" and "Changelog" (superseded by this restructuring into per-module notes). Also noted but intentionally left alone: a handful of unused shadcn sub-exports (`AvatarBadge`, `AvatarGroup`, `AvatarGroupCount`, `CardFooter`, `CardAction`) — normal scaffolding surface area, not worth trimming. Zero automated tests exist anywhere in the project; all verification remains manual (build + browser checks).
- Verified: `npm run build` after every change (zero TS/bundling errors); the root page, login page (button consistency), and the new two-section MFA setup UI were all checked visually in the browser (the MFA setup UI via a disposable local-only preview route, removed before committing).
