# Real Estate & Multi-Currency

**Status:** Done (core) — built within Phase 1, Step 7, alongside [[Portfolio-Dashboard|Portfolio Dashboard]].

## Advanced Real Estate Schema & Multi-Currency Portfolio
- `supabase/migrations/0004_real_estate_and_currency.sql` — adds `assets.metadata` (`jsonb`), the single place category-specific data lives instead of one column per field (see [[Database-Schema|Database Schema]]).
- `src/lib/real-estate.ts` — `RealEstateMetadata` type (address, property type, 4 boolean toggles, 5 fee fields, 3 area fields, floors/rooms/garage counts, year of construction, EPC rating, 5 condition ratings, and a dynamic `ownership: { name, percentage }[]` list) plus its option constants (`PROPERTY_TYPES`, `EPC_RATINGS`, `CONDITION_RATINGS`, `CONSTRUCTION_YEARS`) and `EMPTY_REAL_ESTATE_METADATA` (the form's initial state, one owner defaulted to 100%).
- `src/components/real-estate-fields.tsx` — the expanded Real Estate sub-form: a `Stepper` (+/- buttons) for Floors/Rooms/Garage, a `NumberField` for the fee/area inputs, a `ToggleField` (shadcn `Switch`) for the four booleans, `Select` dropdowns for Type/Year/EPC/Condition, and the Ownership list (add/remove rows, running percentage total shown in `text-success` green when it sums to 100% or `text-destructive` red otherwise).
- `src/components/add-asset-dialog.tsx` — now tracks the selected `category_id` as state (previously untracked) so it can detect when the selected category's name is `"Real Estate"` and conditionally render `<RealEstateFields>` below the standard fields; on submit, serializes that metadata to JSON into a hidden `metadata` field (an empty object for every other category). Also added a Currency `Select` (`src/lib/currencies.ts` — a short curated list: USD, EUR, GBP, AED, CHF, JPY, CAD, AUD, SGD) for the asset's own `current_value`. `DialogContent` gained `max-h-[85vh] overflow-y-auto` since the expanded form is long.
- `src/app/dashboard/actions.ts` — `addAsset` now also reads the `metadata` field, `JSON.parse`s it (returning a clear error on malformed JSON rather than crashing), and inserts it alongside `currency` (which the action already captured from an earlier task).
- `src/lib/fx.ts` — `getExchangeRatesFromUsd(base = 'USD')` fetches live rates anchored to `base`, falling back to a small static rate map (effectively 1:1 for anything it doesn't recognize) if the request fails; `convertAmount(amount, from, to, rates)` converts between any two currencies via that single base-anchored table (one fetch covers every currency pair). **Updated**: switched from `https://api.frankfurter.app` to `https://open.er-api.com/v6/latest/${base}` — Frankfurter doesn't support AED, which this app needs. Also changed the cache from `revalidate: 3600` (1h) to `revalidate: 43200` (12h), since rates only need checking at most twice a day. `src/components/currency-switcher.tsx` — a Client Component `Select` that writes the chosen currency into the `?currency=` URL search param via `next/navigation`, causing the Server Component page to re-render with it.
- `src/app/dashboard/page.tsx` — now accepts a `searchParams` prop, resolves the display currency from `?currency=` (falling back to the signed-in user's `profiles.default_currency`, then `'USD'`), renders `<CurrencySwitcher>` next to "Add Asset", fetches exchange rates in parallel with the existing queries, and converts each asset's `current_value` from its own stored `currency` to the display currency before formatting — the Value column header now shows which currency is being displayed, and the `Intl.NumberFormat` instance uses that currency instead of being hardcoded to `"USD"` regardless of what was actually being shown (a latent bug from the original build).
- For the generic Edit/Delete asset actions added alongside this work (`updateAsset`/`deleteAsset`, the Actions column, `delete-asset-button.tsx`), see [[Portfolio-Dashboard|Portfolio Dashboard]].
- Verified visually in the browser (via a disposable local-only preview route, removed before committing): selecting "Real Estate" correctly expands the full sub-form; the ownership total switches from green to red when the percentages no longer sum to 100; the currency switcher renders and lists the curated currency set; editing a sample Real Estate asset correctly pre-fills every field (name, category, quantity/value/currency, address, type, all four toggles, floors/rooms/garage counts, year, EPC rating, all five condition ratings, ownership total) and the button reads "Save Changes"; the delete button opens the exact confirmation copy requested.
- Not yet verified against a live Supabase instance (no authenticated test session or deployed database available in this environment) — in particular, the actual round-trip of inserting/updating/deleting a Real Estate asset with populated `metadata` has not been exercised end-to-end.

## Off-Plan Property Tracking
- `src/lib/real-estate.ts` — `RealEstateMetadata` gained: `is_offplan` (boolean), `market_valuation` (the property's current fair-market value as entered by the user — kept separate from the asset's `current_value` column, see below), `contract_price`, `adm_fee_percent`/`adm_fee_amount` (Dubai's municipal/ADM registration fee, default 2%), `paid_to_date`, `outstanding_balance`, and `payment_schedule: PaymentMilestone[]` (`{ id, milestone, due_date, amount, percentage, status: 'paid' | 'pending' }`). `nextMilestoneId()` generates a stable client-side id for new rows. `parseRealEstateMetadata` now also defends `payment_schedule` (falls back to `[]` if the stored value isn't an array).
- `src/components/real-estate-fields.tsx` — the toggle row is now under an explicit "Characteristics" heading, with a 5th switch, "Off-Plan Property". When on, an "Off-Plan Payment Tracking" panel appears: Contract Price (SPA), a Municipal/ADM Fee pair (percent input auto-computes the amount from the contract price — editing either one is supported, per spec), and a Payment Schedule milestone builder (milestone name, due date, amount, percentage, Paid/Pending status per row; "+ Add Milestone" / per-row remove). Total Paid to Date and Outstanding Balance are computed automatically (not editable) every time the schedule or contract price changes — Paid to Date is the sum of `amount` across `status: 'paid'` rows; Outstanding Balance is Contract Price minus that sum. Verified visually and interactively: toggling on the switch reveals the panel; entering a contract price of 1,600,000 auto-computed a 32,000 ADM fee (2%); adding a milestone and marking it "Paid" at 160,000 correctly updated Total Paid to Date to 160,000 and Outstanding Balance to 1,440,000.
- **Net equity valuation**: `add-asset-dialog.tsx`'s generic "Value" field is relabeled "Current Market Valuation" (with a "Saved as net equity…" hint) whenever the Real Estate sub-form has `is_offplan` on. At submit time, for an off-plan asset, the handler computes `Net Equity = <entered market valuation> - outstanding_balance`, writes *that* into the `current_value` FormData field actually sent to `addAsset`/`updateAsset` (so portfolio totals reflect real, unencumbered equity rather than the full market value), and stores the raw market valuation into `metadata.market_valuation` so it can be correctly re-shown (not net equity) the next time the asset is edited.
- `src/app/dashboard/actions.ts` — **no changes needed**: `addAsset`/`updateAsset` already treat `metadata` as an opaque JSON blob (`JSON.parse` the whole thing), so every new off-plan field flows through automatically as part of the same `RealEstateMetadata` object the dialog already serializes.
- `src/app/dashboard/page.tsx` — the portfolio table now shows a secondary `Badge` reading "Off-Plan" next to the asset name when `metadata.is_offplan === true`, and beneath the (already net-equity) Value figure, a muted subtitle: `Total: <contract price, converted to the display currency> | Owed: <outstanding balance, converted>`. Verified visually: badge and subtitle both render with the exact requested copy/format.
- Not yet verified against a live Supabase instance — same limitation as the rest of the Real Estate/multi-currency work; no authenticated test session or deployed database available in this environment.

## Linked Loans & Historical Graphs

- `src/lib/real-estate.ts` — added `LinkedLoan` (`amount`, `interest_rate`, `duration_months`, `start_date`) and a `linked_loan` field on `RealEstateMetadata`, deep-merged like `condition`/`ownership` in `parseRealEstateMetadata` so older saved assets default it safely. Added `MAX_ASSET_IMAGES = 3`.
- **Net Equity now also subtracts the loan, for every Real Estate asset (not just off-plan)**: `add-asset-dialog.tsx`'s submit handler always treats the "Value" field as "Current Market Valuation" for Real Estate, preserves the raw figure in `metadata.market_valuation`, and computes `Net Equity = market valuation − linked loan principal − (outstanding off-plan balance, if any)` before writing it to `current_value`. This is a deliberate broadening from the original off-plan-only net-equity logic, since a loan can be linked to any property, not just an off-plan one.
- `src/components/real-estate-fields.tsx` — new "Linked Loan" panel (Total Loan Amount, Interest Rate %, Duration in months, Start Date), placed inside the shared Real Estate sub-form alongside Off-Plan Payment Tracking rather than directly in `add-asset-dialog.tsx`, matching how every other Real Estate section already lives in this file.
- **Multi-image uploader**: `assets.image_base64` (single image) is replaced by `assets.images` (`text[]`, capped at 3 — see [[Database-Schema|Database Schema]] 0006). `add-asset-dialog.tsx`'s image field now shows up to 3 thumbnails with individual remove buttons and an "Add Image" button that disables at the cap; each file is still resized client-side via the existing `resizeImageToBase64`. `dashboard/actions.ts` reads/writes `images` as a JSON-array form field instead of a single base64 string. `dashboard/page.tsx`'s row avatar now shows `images[0]`.
- **`updateAssetValuation(id, newValue, source)`** (`dashboard/actions.ts`) — a standalone server action (separate from `updateAsset`, which edits the full form) for recording a fresh valuation: for Real Estate it recomputes Net Equity the same way as above and updates `metadata.market_valuation`; for everything else `current_value` is set directly. Always inserts a new `asset_history` row (`recorded_date` = today, `value` = the raw entry, `net_equity` = the computed figure, `source`). `source` accepts `'manual' | 'dari' | 'dubailand'`, but only `manual` is functionally wired — there is no DARI or Dubai Land Department API integration in this project, so selecting those options in the UI just tags the source string on a manually entered number (flagged clearly in the UI itself).
- Installed `recharts` and `embla-carousel-react`, plus shadcn `tabs` and `carousel` (declined the CLI's offer to overwrite the already-customized `button.tsx`/`dialog.tsx`; fixed the usual `cn`-from-"cn"-package import bug in both new files).

## All-In Cost Basis, Fee-Aware Net Gain & Currency-Explicit Inputs

- `src/lib/real-estate.ts` gained three calculation helpers, replacing the old "Invested Capital" (purchase price + fees only, no ADM fee) figure:
  - `calculateTotalCost(metadata, fallbackValue)` — `(contract_price ?? purchasePrice ?? fallbackValue) + adm_fee_amount + notaryFees + agencyFees + renovationFees + furnishingFees`. Falls back to the current market valuation when neither a contract nor purchase price has been entered.
  - `calculateCashInvestedToDate(metadata)` — off-plan only: `paid_to_date` (the sum of "paid" milestones) plus every fee, since fees are typically paid up front rather than staged with the contract.
  - `calculateUnrealizedGain(marketValuation, totalCost)` — `{ amount, percent }`, gain against the full cost basis rather than just the purchase price, with `percent` as `null` when `totalCost` is `0` (avoids a divide-by-zero).
  - **Field-name note**: the request's pseudocode used snake_case names (`purchase_price`, `notary_fees`, `agency_fees`, …) that don't exist in this codebase's `RealEstateMetadata` — it uses camelCase (`purchasePrice`, `notaryFees`, `agencyFees`, `renovationFees`, `furnishingFees`). The helpers use the real field names; the calculation logic itself matches what was requested.
- `asset-detail-view.tsx`'s Aperçu tab: the single "Invested Capital" card is now three cards — **Total Property Cost** (`calculateTotalCost`, "All-in cost basis" subtext), **Unrealized Gain** (amount + a green/red percentage `Badge`, "Net gain vs. all-in cost" subtext), and **Cash Invested to Date** (off-plan assets only; falls back to showing Value/m² for non-off-plan Real Estate, so that metric isn't lost).
- **Refresh Valuation dialog now supports entering the new value in any currency**: a currency `Select` (same curated list as the Add/Edit form) sits beside the value input, defaulted to `asset.currency`. On submit, `convertAmount()` (already used by the portfolio table and this page's own charts) converts the entered figure from the selected currency into the asset's own stored currency before calling `updateAssetValuation` — the asset and its `asset_history` rows stay in a single consistent currency. A hint line appears when the selected currency differs from the asset's. `asset-detail-view.tsx` now takes a `ratesFromUsd` prop, fetched server-side in `page.tsx` via the existing `getExchangeRatesFromUsd()` (same pattern as [[Portfolio-Dashboard|Portfolio Dashboard]]'s currency switcher).
- **Currency symbol prefixes on every price/fee input**: `src/lib/currencies.ts` gained `getCurrencySymbol(code)` (via `Intl.NumberFormat(...).formatToParts`). Applied to: `add-asset-dialog.tsx`'s "Current Market Valuation" and the Refresh Valuation dialog's "New Market Value"; `real-estate-fields.tsx`'s `NumberField` helper gained an optional `currency` prop rendering the symbol inside the input (used for Contract Price, Purchase Price, Agency/Notary/Renovation/Furnishing Fees, and Total Loan Amount) and the raw ADM Fee (Amount) input got the same treatment inline (the ADM Fee **%** input intentionally has no currency prefix).
- Verified visually via a disposable preview route (mock off-plan asset, contract price 1,100,000 + fees totaling 49,000 → Total Property Cost 1,149,000; market valuation 1,250,000 → Unrealized Gain 101,000 / +8.8%; paid_to_date 300,000 + fees → Cash Invested to Date 349,000 — all arithmetically verified): all three metric cards render correctly, the Refresh Valuation dialog shows the AED prefix and currency dropdown, and the Edit dialog shows the AED prefix on every price/fee field including the new Linked Loan amount.
- Not yet verified against a live Supabase instance — the Refresh Valuation dialog's actual cross-currency conversion round-trip (e.g. entering a USD value and confirming the AED figure written to `asset_history`) has not been exercised end-to-end, only the underlying `convertAmount()` call path, which is unchanged and already used elsewhere in the app.

## Modal Layout Fix, Paramètres Spec View & Finary-Style Analyse

- **Modal horizontal scroll**: `add-asset-dialog.tsx`'s `DialogContent` is now `w-[95vw] max-w-2xl sm:max-w-3xl max-h-[85vh] overflow-y-auto overflow-x-hidden p-6` (was a narrower, unconstrained-width dialog). Every grid/flex row inside the form and `real-estate-fields.tsx` (images, quantity/value/currency, the Off-Plan milestone builder rows, steppers, ownership rows, fee grids) now carries `w-full min-w-0`, with fixed-width elements (icon buttons, the "%" label, the 2-character stepper count) marked `shrink-0` so they don't force their row wider than its container. The steppers grid and milestone builder's per-row grid also gained explicit `grid-cols-1 sm:grid-cols-*` / `grid-cols-2 sm:grid-cols-6` mobile fallbacks (the steppers grid previously had no mobile breakpoint at all). Verified at both desktop and a 375px mobile viewport via a disposable preview route — no horizontal scrollbar at either size, confirmed by checking the dialog's `scrollWidth`/`clientWidth`/bounding rect directly (both equal, dialog fully within viewport).
- `add-asset-dialog.tsx` gained an optional `trigger?: React.ReactNode` prop so other parts of the app can open the same Add/Edit dialog behind a custom button, rather than only the built-in Edit-icon/"Add Asset" trigger. Used by the Analyse tab's "+ Add Loan" button (see below).
- **Paramètres tab now shows a full read-only spec view** below the Edit/Delete action bar (Real Estate only): Core Property Details (Address, Type, Surface Area, Year, EPC), Material & Condition Ratings (Kitchen/Bathrooms/Flooring/Windows/General), Cost & Fees Basis (Contract or Purchase Price, ADM Fee, Notary/Agency/Renovation/Furnishing Fees), and Financing (loan principal/rate/duration/start date, or "No loan attached"). This is the Characteristics/fee/loan detail that used to live on the Analyse tab, moved here since Analyse was rebuilt around a different layout (below).
- **Analyse tab rebuilt to mirror Finary's layout**, replacing the old Market Performance/Ownership-table/Characteristics/Off-Plan cards with four blocks: **Market Performance** (Price/m², Estimated Market Value, Confidence Level — `metadata.automaticEstimation ? "High" : "Manual"`, reusing the existing toggle rather than adding a new field); **Gross Share** (the primary owner's — first named entry in `metadata.ownership`, or the first entry if none are named — percentage and gross valuation share, with a champagne-gold `ProgressBar`); **Net Share** (that owner's share of `asset.current_value`, which is already net of any off-plan balance and linked loan, with a green `ProgressBar` showing the equity ratio against market valuation, and either the active loan balance or a "+ Add Loan" button that opens the Edit dialog via the new `trigger` prop); and, only when `is_offplan`, the full Payment Milestones table (unchanged from before, just relocated as its own card). `ProgressBar` is a small new inline component (no shadcn `Progress`/Radix dependency needed — a `div` with a width percentage).
- **Scope note**: the previous per-owner Gross/Net "Ownership" table (one row per owner) is replaced by the single-owner Gross/Net Share blocks the task specified, matching Finary's own single-user view. For an asset with multiple owners, only the first named owner's percentage now drives these two cards — full per-owner breakdown is no longer shown on this tab (it was never requested here, and duplicating it would conflict with the new fixed two-card layout).
- Verified visually via a disposable preview route: all four Analyse blocks and all four Paramètres cards render with the expected figures (cross-checked against the mock data by hand), the progress bars fill to the correct percentages, and the "+ Add Loan" trigger correctly swaps to the active-loan-balance display when `linked_loan.amount` is set.
- Not yet verified against a live Supabase instance.
